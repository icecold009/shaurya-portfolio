# Shipping is a design decision

Shipping is often treated as the final step after the real work is done. I have started to think of it as part of the design itself.

## The first release is a question

A useful first release does not try to prove that an entire idea is finished. It asks one clear question: does this solve a real problem for a real person?

That changes what gets built. The smallest version is not automatically the shortest version. It is the version that creates the fastest, most honest conversation with reality.

## Constraints create focus

When a project has a tight boundary, every interaction has to earn its place. Fewer screens make the important screen clearer. Fewer settings make the default more considered. Fewer claims make the product easier to trust.

The constraint is not the enemy of craft. It is often the thing that gives craft somewhere to land.

## Leave room to learn

The best release is one you can observe, explain, and change. Build the narrow path, make the outcome visible, and keep enough flexibility for the next version to be informed by use rather than imagination.
