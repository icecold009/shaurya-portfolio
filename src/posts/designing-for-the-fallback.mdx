# Designing for the fallback

Every product has a moment when its preferred path fails. The network is slow. The model is uncertain. A person taps the wrong thing. That moment is part of the experience, not an exception outside it.

## Graceful is a product quality

An empty state should explain what happened and what can happen next. An uncertain result should show its uncertainty without abandoning the user. A disconnected screen should preserve the work that can still be preserved.

These are small decisions, but they determine whether a tool feels dependable.

## Keep the human option close

Automation is most useful when it gives people leverage, not when it makes them negotiate with a black box. The fallback can be a manual action, an editable suggestion, or simply a clear way to try again.

The important part is that the user remains oriented.

## Design the recovery path first

I like to map the recovery path before polishing the happy path. It exposes hidden assumptions early: what data is required, which choices can be reversed, and where a person needs context instead of another animation.

Resilience is not a technical afterthought. It is a form of respect.
