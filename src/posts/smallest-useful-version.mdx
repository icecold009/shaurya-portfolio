# Find the smallest useful version

Starting a project is easy when the idea is still abstract. The hard part is choosing a first version that can meet the real world before the excitement runs out.

## Reduce the promise

The first version should make one promise clearly. Not five promises vaguely. This is less about cutting features and more about deciding what the project is willing to be known for.

## Build the learning loop

Every useful prototype has a loop: someone tries it, something observable happens, and the result changes what gets built next. If a feature cannot create that loop, it may belong later.

The smallest useful version is therefore not the smallest possible product. It is the smallest product that can teach you something that matters.

## Let the edges stay unfinished

There is a difference between unfinished and neglected. A focused first version can leave secondary paths rough while making its central path thoughtful, clear, and reliable.

That is enough to begin. The rest should be earned by what you learn.
