# What 30 days of AI taught me

I spent 30 days learning how to work with AI more intentionally. The course moved from prompt design and customisation into data workflows, automation, agents, rapid prototyping, and reflection.

The most useful outcome was not one finished app. It was a change in how I think about AI: from treating it as a chatbot that produces text to treating it as a flexible collaborator inside a well-designed process.

## Start with the brief

The first week was about the interaction between a person and a model. I explored custom personalities, NotebookLM, branches in chat, temperature, Google AI Studio, custom GPTs, and the CRISPR and BUILD methods. I also practised prompting properly.

The lesson was simple but important: a good AI response begins with a good brief. The goal, context, constraints, and expected format should be visible before the model starts producing an answer.

## Turn information into something useful

The second phase made the outputs more concrete. I built an app using GPT Canvas, turned a CSV file into an interactive dashboard, converted CSV data into a report, and applied the DIG framework to larger amounts of information.

That connected prompting with analysis. The same source material can become an interface for exploration, a report for communication, or a structured analysis for decision-making. The useful question is not only “What can AI summarise?” but also “What form would make this information easier to use?”

## Move from answers to workflows

The third phase moved from single outputs to repeatable processes. I explored automating simple tasks, automating emails using Slack, making AI agents with n8n, and designing automations for common tasks.

I also explored Claude Code, making a website from a CV using Lovable, building a personal productivity app, and the LOOP virtual framework. This was the point where AI started to feel less like a writing assistant and more like part of a system.

For an AI workflow to be useful, I need to know what triggers it, what context it receives, what action it takes, and where a person reviews the result.

## Prototype before polishing

The final phase focused on making prototypes with AI and Lovable, then applying the 80/20 rule to prototype building. A prototype does not need every feature to be useful. It needs to test the most important assumption quickly enough that I can learn from it.

That mindset changed the way I look at AI-generated interfaces. A fast first version is valuable when it creates a conversation with reality. It still needs direction, verification, and human judgment before it becomes something dependable.

## What changed in my approach

After 30 days, I had a more structured mental model for using AI:

- Start with the job to be done, then choose the tool.
- Make the brief explicit with context, constraints, examples, and an output shape.
- Use the right surface: a notebook, chat branch, custom GPT, canvas, automation platform, or code agent.
- Keep a human checkpoint so important decisions do not become invisible.
- Prototype the riskiest idea before spending time polishing everything around it.
- Treat recap as part of learning. Repetition is what makes a method usable.

## The honest version

Not every day had the same level of novelty. Several days were recaps, and some of the tools and frameworks were introductions that I still need to practise in deeper projects.

That is part of the record. The value of the month was cumulative: prompting, data transformation, automation, agent design, and prototyping began to look like connected parts of one workflow. I also became more aware of the limits of AI-generated output. A fast first version still needs direction, verification, and human judgment.

The biggest shift was from asking “What can this AI tool do?” to asking “What useful process can I design with it?”
